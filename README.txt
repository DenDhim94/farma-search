  О ПРОЕКТЕ
════════════════════════════════════════════════════════════════════════

  «ФармА-Поиск» — веб-приложение для поиска лекарств в аптеках Иркутска
  и их бронирования через корзину.

  Все данные, используемые проектом, предоставляются бесплатно
  из открытых источников интернета. Проект не коммерческий.

  В разработке проекта использовались современные технологии и
  искусственный интеллект — виртуальный помощник «Алиса» от Яндекса.
  

  Что внутри:

  • Клиентская часть — умный поиск лекарств с поддержкой синонимов,
    опечаток и морфологии, корзина брони, оформление заказа
  • Панель персонала (/staff) — просмотр и управление бронями,
    смена статусов
  • Панель администратора (/admin) — статистика, загрузка остатков
    из Excel, интеграция с API «Нейрон Фарм», управление аптеками,
    очистка базы данных
  • Адаптивный дизайн — ПК, планшеты, телефоны (Android, iOS)
  • Разделение ролей — персонал и администратор (с проверкой на бэкенде)
  • Полнотекстовый поиск FTS5 — индексный поиск вместо LIKE (в десятки
    раз быстрее на больших объёмах)
  • Пагинация — по 25 результатов на странице, максимум 100
  • Кэширование — Redis (с fallback на файл и in-memory)
  • WAL-режим SQLite — параллельные чтение и запись без блокировок
  • Батчевая обработка — executemany() для вставки/обновления
    (ускорение загрузки 95 000 строк в 10-30 раз)
  • Умный поиск — 150+ синонимов бренд -> МНН, стеммер, fuzzy-поиск

  1.1. Установка Python
  ─────────────────────
  Скачайте Python 3.10+ с официального сайта: https://www.python.org/downloads/
  При установке на Windows ОБЯЗАТЕЛЬНО поставьте галочку:

  Проверка:
    python --version


  1.2. Создание виртуального окружения
  ────────────────────────────────────
  Откройте терминал (cmd/PowerShell на Windows, Terminal на Mac/Linux)
  в папке проекта:

    cd путь\к\папке\apteka-site

  Windows (PowerShell):
    python -m venv .venv
    .venv\Scripts\activate

  Mac / Linux:
    python3 -m venv .venv
    source .venv/bin/activate

  После активации в строке появится (.venv)


  1.3. Установка зависимостей
  ──────────────────────────
    pip install -r requirements.txt

  Установятся:
    fastapi, uvicorn, openpyxl, python-multipart, requests, redis


  1.4. Установка Redis (опционально, но рекомендуется)
  ──────────────────────────────────────────────────
  Redis используется для кэширования JWT-токена и результатов поиска.
  Без Redis всё работает на файловом кэше + in-memory, но медленнее.

  Ubuntu / Debian:
    sudo apt install redis-server
    sudo systemctl start redis-server

  macOS (Homebrew):
    brew install redis
    brew services start redis

  Windows (через WSL или Docker):
    docker run -d --name redis -p 6379:6379 redis:alpine

  Проверка:
    redis-cli ping
    -> ожидаемый ответ: PONG

  При запуске main.py в консоли появится:
    Redis подключен: redis://127.0.0.1:6379/0
  или, если Redis не установлен:
    Redis недоступен (Timeout...) — кэш в файловом режиме


  1.5. Первый запуск
  ─────────────────
    python main.py

  В терминале появится:
    ФармА-Поиск v9.0 запущен
      Главная:  http://127.0.0.1:8000
      Персонал: http://127.0.0.1:8000/staff
      Админ:    http://127.0.0.1:8000/admin
      Аптеки:   http://127.0.0.1:8000/pharmacies

  Откройте в браузере: http://127.0.0.1:8000

  │  Таблица        │  Назначение                                   │
  ├─────────────────┼───────────────────────────────────────────────┤
  │  excel_stock    │  Товарные остатки (из Excel, API NiRON, демо)  │
  │  excel_stock_fts│  Полнотекстовый индекс FTS5 (виртуальная)      │

  4.2. Схема excel_stock
  ─────────────────────

  Колонка                Тип         Описание
  ─────────────────────────────────────────────────────────────────
  id                    INTEGER     Автоинкрементный PK
  dep_code              TEXT        Код аптеки
  dep_name              TEXT        Название аптеки
  product_name          TEXT        Полное название товара
  product_name_lower    TEXT        Название в lowercase (для поиска)
  qty                   REAL        Остаток (количество)
  price                 REAL        Цена в рублях
  expiry               TEXT        Срок годности (ДД.ММ.ГГГГ)
  source                TEXT        Источник данных:
                                    'excel' — загружено из Excel
                                    'api'   — получено из API NiRON
                                    'demo'  — демо-данные
  updated_at            TEXT        Дата и время последнего обновления
                                    Формат: YYYY-MM-DD HH:MM:SS

  Индексы:
    idx_stock_name_lower  ON excel_stock(product_name_lower)
    idx_stock_dep_code    ON excel_stock(dep_code)
    idx_stock_price       ON excel_stock(price)
    excel_stock_fts       — виртуальная таблица FTS5 (полнотекстовый поиск)

  4.3. Схема bookings
  ───────────────────

  Колонка         Тип      Описание
  ─────────────────────────────────────────────
  id              TEXT     UUID брони (BR-XXXXXXXX)
  items_json      TEXT     JSON: [{name, price, qty, dep_code, dep_name}]
  total_price     REAL     Сумма брони
  customer_name   TEXT     Имя клиента
  customer_phone  TEXT     Телефон
  status          TEXT     active / done / cancelled / expired
  created_at      TEXT     Дата создания (ISO)

  4.4. FTS5 — полнотекстовый поиск
  ────────────────────────────────
  Виртуальная таблица excel_stock_fts использует FTS5 (встроен в SQLite).
  Поиск через MATCH вместо LIKE '%term%' — индексный, в десятки раз быстрее.
  Триггеры автоматически обновляют FTS-индекс при вставке/обновлении/удалении.

  Запрос:
    SELECT es.*, p.address, p.phone
    FROM excel_stock_fts fts
    JOIN excel_stock es ON es.id = fts.rowid
    LEFT JOIN pharmacies p ON CAST(es.dep_code AS INTEGER) = p.code
    WHERE excel_stock_fts MATCH ?
    ORDER BY rank
    LIMIT ? OFFSET ?


════════════════════════════════════════════════════════════════════════
  5. УМНЫЙ ПОИСК
════════════════════════════════════════════════════════════════════════

  5.1. Этапы поиска
  ────────────────
  1. Валидация — длина 2-100 символов, только буквы/цифры/пробелы
  2. Нормализация — trim, lowercase, удаление лишних пробелов
  3. Синонимы — замена брендов на МНН (150+ соответствий)
     Пример: Нурофен -> ибупрофен, Но-шпа -> дротаверин
  4. Стеммер — отсечение русских окончаний
     (-ая, -ое, -ые, -ой, -ыми, -ами, -ах, -ов, -ев, -ие, -ые и др.)
  5. FTS5 MATCH — полнотекстовый поиск по индексу
  6. Ранжирование — rank из FTS5 (встроенный BM25)

  5.2. Синонимы (категории)
  ────────────────────────
  • Жаропонижающие / НПВС:
    Нурофен -> ибупрофен, Панадол -> парацетамол, Найз -> нимесулид

  • Сердечно-сосудистые:
    Конкор -> бисопролол, Энап -> эналаприл, Капотен -> каптоприл,
    Лозап -> лозартан

  • Сахарный диабет:
    Глюкофаж -> метформин, Диабетон -> гликлазид

  • Бронхолёгочные:
    Вентолин -> сальбутамол, Беродуал -> ипратропия бромид + фенотерол

  • Гепатопротекторы, пробиотики, витамины, женское здоровье,
    мочегонные, противогрибковые и др.

  Словарь расширяется в main.py — переменная SYNONYMS_DICT.

════════════════════════════════════════════════════════════════════════
  7. КЭШИРОВАНИЕ
════════════════════════════════════════════════════════════════════════

  7.1. Кэш поиска (60 секунд)
  ──────────────────────────
    Redis-ключ:
      search:{query}|{page}|{limit} — JSON-результат (TTL 60с)

    In-memory:
      SEARCH_CACHE = {} — dict, fallback при недоступности Redis

  7.2. Кэш JWT-токена API NiRON
  ────────────────────────────
    TTL: 24 часа (86400 секунд)
    Buffer: 30 секунд (токен считается невалидным за 30с до истечения)

    Структура token_cache.json:
    {
      "access_token": "eyJhbGciOi...",
      "expires_at": 1790698784,
      "expires_at_iso": "2026-09-29 16:19:44",
      "created_at": "2026-09-28 16:19:44"
    }

    Логика:
    1. Проверка Redis -> валиден? -> возврат из Redis
    2. Проверка файла -> валиден? -> перенос в Redis -> возврат
    3. Запрос нового токена -> сохранение в Redis + файл -> возврат

    Очистка кэша при любой ошибке:
    • HTTP-ошибка -> удаление файла + Redis
    • Нет access_token -> удаление файла + Redis
    • Таймаут / исключение сети -> удаление файла + Redis
    • Файл повреждён -> удаление файла
    • Токен истёк -> удаление файла

    Старый токен НИКОГДА не возвращается при ошибке.


════════════════════════════════════════════════════════════════════════
  8. СЛИЯНИЕ ОСТАТКОВ (merge_stock) — v9.0 ОПТИМИЗИРОВАН
════════════════════════════════════════════════════════════════════════

  При загрузке данных из Excel или API NiRON используется слияние,
  а не полная замена таблицы. В v9.0 реализована батчевая обработка:

  ┌──────────────────────────────────────────────────────────────┐
  │  Ситуация                              │  Действие          │
  ├───────────────────────────────────────┼────────────────────┤
  │  Товар в БД и в incoming, qty совпадает│  Не трогаем        │
  │                                       │  updated_at прежний│
  ├───────────────────────────────────────┼────────────────────┤
  │  Товар в БД и в incoming, qty differs  │  UPDATE qty,       │
  │                                       │  updated_at=now    │
  ├───────────────────────────────────────┼────────────────────┤
  │  Товар в incoming, нет в БД           │  INSERT            │
  ├───────────────────────────────────────┼────────────────────┤
  │  Товар в БД, нет в incoming           │  DELETE            │
  └───────────────────────────────────────┴────────────────────┘

  Оптимизация v9.0:
  • Вместо построчных execute() — executemany() батчами
  • Ускорение на 95 000 строк: 10-30 раз
  • Один commit на всю операцию

  Статистика слияния в ответе:
    inserted  — добавлено новых
    updated   — обновлено (цена/остаток изменились)
    deleted   — удалено (нет в новых данных)
    skipped   — пропущено (без изменений)

  9. ПОДСТАНОВКА АПТЕК
════════════════════════════════════════════════════════════════════════

  Логика сопоставления:
  1. Точное совпадение dep_code
  2. Точное совпадение dep_name (регистронезависимо)
  3. Частичное совпадение dep_name

  12. ИНТЕГРАЦИЯ С API «НЕЙРОН ФАРМ» (NiRON)
════════════════════════════════════════════════════════════════════════

  12.1. Аутентификация
  ───────────────────
    Endpoint: {API_BASE_URL}/auth/token
    Метод:   POST
    Тип:     OAuth2 client_credentials
    Grant:   client_credentials
    Результат: access_token (JWT, 24 часа)

  12.2. Получение остатков
  ───────────────────────
    Шаг 1: Получение списка отделений
      Endpoint: {API_BASE_URL}/dict/departments
      Метод:    GET
      Headers:  Authorization: Bearer {token}

    Шаг 2: Для каждого отделения — получение остатков
      Endpoint: {API_BASE_URL}/stock
      Метод:    GET
      Параметры: department={dep_code}, cursor={cursor}
      Headers:  Authorization: Bearer {token}
      Пагинация: cursor передаётся из ответа до тех пор,
                 пока не вернётся пустой cursor

    Шаг 3: Фильтрация
      • Пропускаются позиции с deleted=true
      • Отрицательный qty обрезается до 0

    Шаг 4: Слияние с базой
      merge_stock(conn, all_items, "api") — батчевое (v9.0)

  12.3. Ручной запуск
  ──────────────────
    Панель администратора -> «Получение данных из API NiRON» ->
    кнопка «Получить данные вручную»

    В панели статуса отображается:
      • Последний запрос (дата/время)
      • Статус (успех/ошибка)
      • Получено записей
      • Код ошибки (если есть)
      • Описание ошибки (если есть)
      • Всего запросов (счётчик)
      • Успешных запросов (счётчик)

  13. СКРИПТЫ ОБСЛУЖИВАНИЯ
════════════════════════════════════════════════════════════════════════

  13.1. Очистка базы данных (cleanup_db.py)
  ────────────────────────────────────────
  Удаляет:
    • Брони со статусом done/cancelled/expired старше N дней (по умолчанию 30)
    • Остатки, не обновлявшиеся более N дней (по умолчанию 14)
    • Выполняет VACUUM для сжатия файла БД

  Команды:
    python cleanup_db.py --dry-run              # посмотреть, что удалится
    python cleanup_db.py                         # очистка по умолчанию (30/14 дней)
    python cleanup_db.py --bookings-days 7 --stock-days 3  # агрессивная очистка

  Автоматизация через cron (Linux/macOS):
    0 3 * * * cd /path/to/project && python cleanup_db.py >> cleanup.log 2>&1

  Также доступна через веб-интерфейс:
    Панель администратора -> «Очистка базы данных» ->
    кнопка «Просмотр» (dry run) / «Очистить»


  13.2. Переименование проекта (rename_project.py)
  ───────────────────────────────────────────────
  Заменяет все варианты написания 
  во всех .py, .html, .css, .json, .txt, .md файлах.

  Команды:
    python rename_project.py --dry-run    # сначала посмотреть замены
    python rename_project.py              # применить


  13.3. Деплой (deploy.py)
  ────────────────────────
  Применяет миграции БД и перезапускает сервер.

  Команды:
    python deploy.py --migrate            # только миграции БД
    python deploy.py --restart            # миграции + перезапуск
    python deploy.py                      # проверка + миграции
    python deploy.py --restart --service farmapoisk   # через systemd
